# ForgeGuard backend API contract

The single source of truth is **[`docs/API.md`](../docs/API.md)** in the repo root (Pydantic models:
`backend/app/schemas.py`). This file only explains how `src/api.ts` maps that contract to the UI types in
`src/types.ts`. If the two ever disagree, `docs/API.md` wins - fix `src/api.ts`.

Base URL = `VITE_API_BASE_URL`. Live mode needs `VITE_USE_MOCK=false`. Errors: HTTP 4xx/5xx with
`{"error": "message"}`, shown to the user as-is. CORS: `npm run dev` serves on `http://localhost:3000`, so add it
to `FRONTEND_ORIGINS` in `backend/.env` (see `docs/RUN_LOCAL.md`); the backend default allows only `:5173`.

## Endpoints used

| Method | Path | `src/api.ts` | Timeout |
|---|---|---|---|
| POST | `/api/analyze/demo/{dataset_id}` | `runDemo` | 60 s |
| POST | `/api/analyze` (multipart `readings`, optional `notes`) | `uploadReadings` | 60 s |
| GET | `/api/runs` | `getRuns` (History; in backend memory, newest 20, lost on restart) | 30 s |
| GET | `/api/runs/{run_id}` | `openRun`, page refresh | 30 s |
| POST | `/api/runs/{run_id}/explain/{machine_id}` | `explainMachine` | **120 s** |
| GET | `/api/llm/status` | `getLlmStatus` | 15 s |

**Why 120 000 ms for explain:** one real AMD explanation takes about 25 s (seen 12-36 s, recently 35-52 s).
If the AI reply is invalid (bad JSON or empty findings) the backend makes one repair call, so two slow calls
can approach 100 s. `docs/API.md` asks for at least 90 s; 120 s adds headroom so the browser never aborts a
request the backend is still finishing (that would waste the team's shared $1/day AMD limit).

## Mapping (live mode)

| Backend (`docs/API.md`) | UI |
|---|---|
| `cases[]` (already in queue order, never re-sorted) | queue: `rank` = position, `summary` = first anomaly `reason` (else first `context` message) |
| `readings[]` filtered by `machine_id` | chart rows; a row is unusual if its `row_id` is in an anomaly's `row_ids` |
| `anomaly_id`, `sensor`, `peak` + `unit`, `method` (`limit` / `zscore`) + `reason` | anomaly cards and evidence drawer |
| `linked_notes[{note_id, relation}]` | note label "before/during/after A-n"; notes not in `evidence_ids` are labelled background |
| `MachineCase.context[].message` | "Data warnings" (context only, never evidence) |
| `sensors` (`kind == "quality"` skipped) | chart sensors and limits; `warn_high/low == null` -> "No fixed limit" |
| `dataset.name`, `dataset.attribution`, `!dataset.synthetic` | dataset name, attribution line, real-data flag |
| `explanation.summary / findings[].statement / possible_causes[].cause / recommended_checks[].action + reason / missing_information / uncertainty` | report sections; cited IDs stay visible |
| `unsupported[{section, index}]` | that finding is marked unsupported; causes/checks get "[not supported by evidence]" |
| `provenance.provider / model / hardware_label / latency_ms / cached` | "Generated by `model` via `provider` on `hardware_label` in x s" (shown exactly as returned) |
| `explanation == null` | page error alert with `error` + `fallback_summary` - no AI box |
| `/api/llm/status` `provider / model / hardware_label / reachable / last_latency_ms / error` | Status page |

## Badge (from `provenance.provider` ONLY, never hard-coded)

- `mock` -> "MOCK - not AI output"
- `saved` -> "saved" (a stored real AMD report)
- `amd_token_factory` -> "AI explanation" + red **AMD** badge, with `model` and `hardware_label` as returned
- `gemini` -> "AI explanation", no AMD badge
- `cached: true` -> " (cached)" appended
